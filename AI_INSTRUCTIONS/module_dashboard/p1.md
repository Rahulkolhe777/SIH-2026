**Optimize Component Re-rendering**

Review the application and improve its rendering performance by ensuring that **only the components affected by a state or data change are re-rendered**.

The goal is to avoid unnecessary re-renders across unrelated parts of the UI.

For example, if the **sidebar state or content changes**, only the components that actually depend on that sidebar state should re-render. The rest of the page, such as the main/right content area, should remain unchanged unless its own dependencies have changed.

Apply this principle **generically across the entire application**, not just to the sidebar example.

### Requirements

* Identify unnecessary or cascading re-renders.
* Keep state as close as possible to the components that actually use it.
* Avoid putting frequently changing state in unnecessarily high-level/global components.
* Split components where necessary so independent sections can render independently.
* Use appropriate memoization (`React.memo`, `useMemo`, `useCallback`, selectors, etc.) only where it provides a real benefit.
* Avoid passing changing props through large component trees when they are not needed.
* Ensure context/state updates do not cause unrelated consumers to re-render unnecessarily.
* Prefer fine-grained state management and subscriptions/selectors where appropriate.
* Do not optimize by blindly adding memoization everywhere; first identify the actual rendering dependency.
* Preserve existing functionality and behavior while improving rendering efficiency.

### General principle

**A component should re-render only when something it actually depends on has changed.**

Think in terms of **render boundaries and dependencies**: independent UI sections should be able to update independently rather than causing the entire parent tree or unrelated sibling components to re-render.
